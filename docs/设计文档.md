## 1. 产品定位与设计目标

### 1.1 一句话定位

一个**只活在用户本机**的 Markdown 写作工具：左边写、右边即时渲染，文件永远落在用户选的目录里。

### 1.2 设计目标（优先级从高到低）

| 优先级 | 目标 | 落地体现 |
| --- | --- | --- |
| P0 | **零云同步** | 架构中不存在任何网络层后端；`fsApi` 只有本地读写通道 |
| P0 | **启动快、输入不卡** | Markdown 解析放 Web Worker；CodeMirror 6 取代 Monaco；Tauri 取代 Electron |
| P0 | **体积可控** | 安装包 2~3MB（Tauri + 系统 WebView） |
| P1 | **双形态同一套代码** | 桌面端（Tauri，Rust 读盘）/ 浏览器端（File System Access API），上层无感知 |
| P1 | **不静默失败** | 任何文件操作异常都经 `Banner` 显式呈现；错误文案做了中文映射 |
| P2 | **界面克制** | 单色系 + 少量强调色，左右中缝可拖，无多余面板 |

### 1.3 明确不做的事（Non-Goals）

- 不做云同步 / 多端协作 / 账号体系 —— 这是产品底线，不是待办。
- 不做富文本 WYSIWYG，编辑体验锚定 Markdown 源码。
- 不做插件系统（当前版本）。
- 不做客户端自动更新（发版靠 GitHub Actions 打 tag 出包）。

### 2.2 关键架构决策（ADR 摘要）

| # | 决策 | 理由 | 被否决的方案 |
| --- | --- | --- | --- |
| ADR-1 | 用 **Tauri 2 + Rust** 而非 Electron | 安装包 2~3MB、内存低、复用系统 WebView、原生文件权限模型清晰 | Electron（体积大、冷启动慢） |
| ADR-2 | 用 **CodeMirror 6** 而非 Monaco / TinyMCE | 体积约为 Monaco 的 1/5，扩展模型（Compartment）完美适配主题切换，自带搜索/多光标/缩进 | Monaco（过重） |
| ADR-3 | Markdown 解析跑在 **Web Worker**，且主线程只持有一份预览 HTML | 大文档不卡主线程，输入不丢帧 | 主线程同步渲染（大文档掉帧） |
| ADR-4 | 文件系统访问收敛到 **单一 `fsApi` 门面**，双模式同签名 | 业务代码零环境判断，`isTauri` 只在 `fs.ts` 与状态层出现两次 | 各组件自行判断运行环境 |
| ADR-5 | 状态用 **zustand 单 store**，不做 Context + reducer | 样板极少、选择器订阅可精准重渲染；跨组件（MenuBar/Sidebar/DocBar/StatusBar）共享同一份数据 | Redux Toolkit（样板重） |
| ADR-6 | 预览渲染链路固定为 **Worker 渲染 → DOMPurify 消毒 → `dangerouslySetInnerHTML`** | 即使 `markdown-it` 开了 `html: true`，出口仍强制消毒，杜绝注入面 | 直接 innerHTML |
| ADR-7 | 双形态同一份前端产物（`base: './'`），Tauri 只做宿主 | 免维护两套 UI | 前端按平台分仓 |

## 3. 技术选型

| 层 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| 桌面运行时 | Tauri 2（Rust） | 2.x | 见 ADR-1 |
| UI 框架 | React | 18.3 | 生态最成熟 |
| 语言 | TypeScript（strict + noUnusedLocals/Parameters） | 5.6 | 类型安全，`tsc --noEmit` 进 build |
| 构建 | Vite | 5.4 | HMR 极快；`worker.format: 'es'` 支持 ES Module Worker |
| 编辑器 | CodeMirror 6（state/view/commands/lang-markdown/search/lint/theme-one-dark） | 6.x | 见 ADR-2 |
| Markdown | markdown-it（html / linkify / typographer） | 14 | 插件生态齐全 |
| 扩展 | markdown-it-anchor / task-lists / footnote | 9 / 2 / 4 | 标题锚点、任务列表、脚注 |
| 代码高亮 | highlight.js | 11 | 语言覆盖广 |
| 消毒 | DOMPurify | 3.1 | 导出/打印出口统一净化（见 ADR-6） |
| 状态 | zustand | 4.5 | 见 ADR-5 |
| 图标 | lucide-react | 0.451 | 线性一致 |
| 样式 | 纯 CSS + CSS 变量（`tokens.css`） | - | 零运行时、主题切换只换 `[data-theme]` |
| 工具链约束 | Node ≥ 18（`.node-version` = 22.23.3，fnm 固定） | - | Vite 5 不支持 Node 16 |

> v0.2.0 起 `markdown-it` / `highlight.js` / `DOMPurify` **只用于导出与打印**，
> 屏幕上的所见即所得由 `src/lib/wysiwyg.ts` 的 CodeMirror 装饰实现，不依赖这三者。

### 5.0 v0.2.0 架构调整（先读这一节）

#### 5.0.1 三处结构性变化

#### 5.0.2 WYSIWYG 为什么用「装饰」而不是「富文本」

实现所见即所得有两条路：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| 富文本（ProseMirror/TipTap） | 文档换成富文本 DOM，Markdown 只是导入导出格式 | 需要维护「富文本 ↔ Markdown」双向序列化，**这是 bug 温床**（光标跳、列表塌陷、粘贴丢格式） |
| **装饰（当前采用）** | CodeMirror 继续编辑**纯 Markdown 源码**，只是把标记藏起来、把样式挂上去 | 文档始终是合法 Markdown，导出/复制/另存为零成本；代价是「所见」是假的，只对行级/行内标记有效（**表格**已用 `Decoration.replace` + Widget 补齐；脚注、定义列表、HTML 块仍是源码） |

核心模块是 `src/lib/wysiwyg.ts`（约 400 行），关键设计：

1. **只编辑源码，永不反序列化** —— 标记隐藏靠 `Decoration.replace({})`（零宽替换），
   语义样式靠 `Decoration.mark` / `Decoration.line`。
2. **光标所在行的标记按「位置粒度」显隐** ——判据是「光标是否落在**这一小段标记**里」
   （`inMark(ctx, from, to)`，`ctx.cursorPos >= from && cursorPos < to`），
   而不是「光标是否在本行」。原先按行判断时，点一下正文 `#` 就冒出来，
   等于「一点就破功」。**块级前缀**（`#`/`>`/`- `/```/`---`/表格分隔行）则一律隐藏，
   光标进去也不露，替代路径是「光标停在行首按回车删掉效果」。
3. **围栏是跨行状态，所以线性扫描而非只扫视口** —— 若只扫 `visibleRanges`，
   围栏开头在视口上方时会把代码块内容当普通段落解析。实测代价可接受（万行文档 < 1ms）。
4. **行内规则会嵌套命中，必须去重** —— `**粗**` 里的 `*` 也会命中斜体规则。
   用 `claimed: [from, to][]` 记录已占用区间，重叠的命中直接跳过。
5. **`claimed` 覆盖的区间必须与 `hideInline` 藏起来的区间一致**（v0.3.6 新增）。
   链接规则曾写成 `head: 1, tail: 0`（只藏 `[`），而 `claimed` 却 claim 了整段
   `[文字](url)`：多出来的 `](url)` 既没被隐藏、又被 mark 装饰标记为已占用，
   CodeMirror 的 `posAtCoords` 无法把它映射回文档位置 ——
   实测点 `]`、点 `(`、点 URL 任意位置，光标 offset 全部卡在链接文字末尾不动。
   现在链接用 `tail: -1` 哨兵，表示「藏到可见内容（`m[1]`）结束为止」，整段消失。
   **加新规则时的自检**：DOM 里不该出现任何未被 `hideInline` 覆盖的原始字符。
6. **两个已踩过的坑（改这个文件前务必知道）**：
   - `view.visibleRanges` 在 **ViewPlugin 构造阶段为空数组**，直接取 `[length-1]` 会抛
     `Cannot read properties of undefined (reading 'to')`，而 CodeMirror 只会打印一行
     `CodeMirror plugin crashed`，极难定位。必须兜底成 `state.doc.lines`。
   - 装饰必须按 `from` 升序加入，乱序会抛 `Ranges must be added sorted`。
     因此统一收集到数组后交给 `Decoration.set(list, true)` 排序，**不要手工用 `RangeSetBuilder`**。

#### 5.0.3 CSS 权重陷阱

`global.css` 里所有 Markdown 语义样式都必须写成 `.editor-host .cm-md-*`（权重 0,2,0），
不能只写 `.cm-md-*`（0,1,0）—— 否则会被同样作用于 `.cm-line` 的
`.editor-host .cm-line { padding: 0 }`（0,2,0）整条盖掉，
表现为**列表缩进和圆点静默消失**（不报错，只是看不见）。这个坑真实发生过。

#### 5.0.4 无工作区也能写

- `OpenTab.path` 允许为 `null`（未命名文档），标签用稳定的 `id` 作 key —— 这是本次把
  `active` 从「path」改成「id」的根本原因。
- `save()` 检测到 `path === null` 时自动转入 `saveAs()`，用户无需先想好存哪。
- 浏览器端另存为靠 `showSaveFilePicker` 返回的 `FileSystemFileHandle` 存进 `fs.ts` 的
  `looseFiles: Map`，**后续保存必须复用同一个句柄** —— 浏览器不允许凭路径字符串重新拿句柄。
- 桌面端保存路径是绝对路径；浏览器端没有绝对路径，虚拟路径就是文件名本身。

#### 5.0.5 v0.3.0：单文档模式与未保存拦截

需求是「不支持同时多个标签页，点其他文件直接覆盖，上一个未保存则提示」。落地时拆成三块：

**1. 单文档不变量**

`tabs` 数组**恒为 0 或 1 个元素**。保留数组结构（而不是换成单个 `doc` 字段）是为了让
`Editor` / `StatusBar` / `FileTree` 的取值逻辑不必大改，但**不要再往里 push 第二个文档**。
所有赋值都走 `single(doc | null)` 这个辅助函数，它是唯一允许写 `tabs` 的地方。

**2. `guard(action)` —— 统一的切换入口**

```mermaid
flowchart TD
    A["新建 / 打开文件 / 打开文件夹 / 关闭文档"] --> B["guard(action)"]
    B --> C{"当前文档 dirty?"}
    C -->|否| D["直接执行 action"]
    C -->|是| E["set pendingSwitch = action<br/>对话框显示"]
    E --> F{"用户选择"}
    F -->|保存| G["await save()"]
    G --> H{"保存后仍 dirty?"}
    H -->|是<br/>（另存为被取消）| I["中止切换<br/>内容不丢"]
    H -->|否| J["执行原 action"]
    F -->|放弃| D
    F -->|取消| K["清空 pendingSwitch<br/>留在原文档"]
```

两个容易写错的点：

- **「保存」后必须复查 dirty**：用户在另存为对话框点了取消时，`save()` 什么都没做但也没报错。
  若不检查就继续切换，等于「点了保存却丢了内容」——这比不弹框更糟。
- **拦截必须发生在读文件之后**：先 `readFile` 成功再 `guard`，
  免得用户先选完文件才发现上一个文档有未保存内容。若读取失败则不弹框（没什么可切换的）。

`openFile` 另有一条短路：点当前正打开的同一文件直接返回，**不弹未保存提示**——
否则用户点自己正在编辑的文件会被无意义地拦一次。

**3. 侧栏显隐只有一个入口**

按钮放在**底部栏左下角**（`DocBar`），侧栏页签行右侧不再有折叠箭头，
隐藏时也**不显示任何把手小竖条**（原 `SidebarHandle` 已删除）。
`setPane()` 相应改为「只切页签、顺带确保侧栏可见」，不再做「再点一次当前页签 = 折叠」
的隐式折叠 —— 那会形成两个控制入口，用户不知道该点哪个。

#### 5.0.6 v0.3.1：两处交互修正

**1. 「刚打开文档时首行标题露出 `#`」**

现象：打开 md 后首行 H1 显示成 `# 标题`，在正文任意位置点一下就恢复正常。

根因：`Editor.tsx` 打开文档时调 `view.focus()`，光标落在**位置 0**；
而 `wysiwyg.ts` 判断「哪一行露原始标记」只看 `selection.main.head` 所在行，
于是第 1 行（恰好常是标题行）被当成光标行。**「刚打开」和「用户把光标放进去」
在 position 0 上无法区分**，这是问题的本质。

修法：把判定从「光标在哪行」改成 `activeLine(view)`，三个条件全满足才露标记：

```ts
function activeLine(view: EditorView): number {
  if (!view.hasFocus) return -1                    // ① 编辑器没焦点
  const head = view.state.selection.main.head
  if (head === 0 && view.state.selection.main.empty) return -1  // ② 刚打开
  return view.state.doc.lineAt(head).number        // ③ 用户确实动过
}
```

配套改动：**ViewPlugin 的重算条件必须加 `focusChanged`**。
原先只有 `docChanged / selectionSet / viewportChanged`，
点进文件树再点回编辑器时光标没动，装饰不会重算，「哪一行露标记」就滞后了。
这个坑很隐蔽 —— 功能看起来是好的，只是焦点切换时不更新。

**2. 底部栏去掉文档标签**

单文档模式下底部再显示文档名/未保存圆点是冗余信息（状态栏已有保存状态）。
`DocBar` 现在只留左下角的侧栏显隐按钮；「关闭文档」挪到文件菜单末尾，避免丢失入口。
当前打开的文件改为在左侧文件树高亮 —— 单文档下这是唯一需要指明「我在编辑哪个」的地方，
所以要比普通 hover 更醒目：左侧 2px 强调色竖条 + 加粗 + 强调色文字 + 浅色底。

### 5.1 文件系统桥 `src/lib/fs.ts`（整个项目最核心的抽象）

这一个文件把「桌面端 Rust 读盘」和「浏览器端 File System Access API」拍成同一组接口，
上层（`store.ts`、组件、`export.ts`）只用 `fsApi`，永远不关心自己在哪个环境。

```mermaid
flowchart LR
    CALL["调用方 fsApi.*"] --> Q{"isTauri?<br/>window.__TAURI_INTERNALS__"}
    Q -->|是| T["tauriInvoke → commands.rs"]
    Q -->|否| CHK{"rootHandle 已授权?"}
    CHK -->|是| B["File System Access API"]
    CHK -->|否| ERR["抛『未选择文件夹』"]
```

统一 API：

| 方法 | 桌面端实现 | 浏览器端实现 |
| --- | --- | --- |
| `pickFolder()` | `@tauri-apps/plugin-dialog` 的 `open({directory:true})` | `showDirectoryPicker({mode:'readwrite'})` |
| `listDir(path)` | `invoke('read_dir')` | `handle.entries()` 递归到目标目录 |
| `readFile(path)` | `invoke('read_file')` | `getFileHandle().getFile().text()`；无工作区时查 `looseFiles` |
| `writeFile(path, content)` | `invoke('write_file')` | `createWritable()`；无工作区时查 `looseFiles` |
| `openFile()` | `open()` + `read_file` | `showOpenFilePicker()`，句柄存入 `looseFiles` |
| `saveAs(name)` | `save()` 返回绝对路径 | `showSaveFilePicker()`，句柄存入 `looseFiles` |
| `adoptParentOf(path)` | 记下父目录为工作区 | 空操作（浏览器无此概念） |
| `persistRoot / restore` | `localStorage['kore-root']` | IndexedDB `kv` 对象存储存 `FileSystemDirectoryHandle` |
| `regrant / forgetRoot / hasRestoredHandle` | 空操作 / 清 localStorage | `requestPermission` / 删 IndexedDB 记录 |

#### 5.1.1 浏览器端的「虚拟路径」约定（易错点，务必遵守）

浏览器里**没有真实绝对路径**，因此统一用一条规则：

> 虚拟路径的第一段**永远是根目录的名字**（例如打开 `gateway` 目录，`gateway/技术方案.md`）。
> 解析时 `relParts()` 先把这段根名剥掉，剩下的才是相对段；生成子项时必须重新拼上根名前缀。

`src/lib/fs.ts` 的注释明确记录了这条规则的由来：生成子项时漏掉根名前缀 → 解析时按字符串长度硬切 →
展开子目录报「找不到目录」（对应提交 `d2a64fc fix(fs): 修复浏览器模式展开子目录报『找不到目录』`）。
**任何新增路径拼接逻辑都必须复用 `relParts()`，不要自己 `split('/')`。**

#### 5.1.2 权限恢复与三个逃生口

浏览器安全模型要求「重新授权」必须由**用户手势**触发，所以设计上留了三道兜底：

1. `restore()` 返回 `{ name, granted }`，`granted=false` 时不上报失败，而是交给 `Banner` 渲染一个「重新授权」按钮（`notice.action='regrant'`）。
2. `init()` 里对恢复流程套了 `withTimeout(…, 3000)`：IndexedDB 反序列化句柄卡死时**宁可不恢复也不让页面卡住**。
3. `?reset` 查询参数：`store.init()` 检测到即 `forgetRoot()` 并在 Banner 提示重选目录——当恢复流程把页面拖死、界面都点不动时的最后自救手段。

#### 5.1.3 排序规则一致

- 浏览器端：`localeCompare(name, 'zh')`，目录优先。
- Rust `read_dir`：目录优先，再 `to_lowercase()` 后按名字比较。
两端肉眼结果一致，目录树不会出现「桌面端和浏览器端顺序不同」。

#### 5.1.4 文件树的新建 / 重命名 / 删除 / 定位（v0.3.9 起）

右键菜单（`FileTree.tsx` + `TreeMenu.tsx`）：**新建文件**（不写扩展名自动补 `.md`）、
**新建文件夹**、**重命名**、**打开文件位置**、**删除**。

两条铁律：

1. **新建 / 重命名 / 删除都是真落盘**，不是只改内存等保存时再写。
   需求原话是「在 Kore 中的文件操作，在电脑要同步」——
   与 `fsApi.createFile / createDir / rename / remove` 一一对应，
   桌面端走 `commands.rs` 的
   `create_file / create_dir / rename_path / remove_file / remove_dir`。
2. **不用 `window.prompt` / `window.confirm`**：
   Tauri 的 WebView **不支持**它们（`prompt()` 返回 null、`confirm()` 恒 false，
   而且不报错），在桌面端会表现为「点了没反应」。所以自己画弹窗（`TreeMenu.tsx`）。

**新建文件用 `create_new(true)`** 而不是 `write`：它在打开时就要求文件不存在，
连「检查完到写入之间被别的程序抢先创建」这种竞态也挡掉。
静默覆盖用户的文件是不可接受的，重名一律报错。重命名同理：目标已存在直接拒绝，不覆盖。

**重命名（未发布，攒批）**：`fsApi.rename` 桌面端走 Rust 的 `fs::rename`
（文件/目录通用）。`store.renameEntry` 成功后会把打开的标签路径迁到新路径
（也包括「改名的是当前文件所在目录」这种情况），并清掉旧目录及其整棵子树的
`dirs` / `expanded` 缓存，避免缓存里留下旧路径。工作区根目录不提供重命名
—— 改名会打乱 `rootPath` 与所有已缓存路径。浏览器模式没有原生 rename：
文件用「复制字节 → 建新 → 删旧」模拟，目录明确拒绝并提示用桌面版。

**「打开文件位置」自己 spawn 进程**（Windows `explorer /select,<path>`、
macOS `open -R`、Linux `xdg-open`），没走 opener 插件的 `reveal_item_in_dir`：
后者的路径受前端 scope 约束，默认不放行任意绝对路径。一律 `spawn` 不 `wait`
—— explorer.exe 成功时也会返回非 0 退出码，等它只会带来误报。

**删除成功不弹提示（v0.3.15）**：`store.deleteEntry` 的成功分支不再写 `notice`。
文件树里条目消失就是最直接的反馈，顶部再压一条「已删除「xxx」」info 横幅纯属干扰；
只有删除**失败**（权限不足、文件被占用、路径已不存在）才走 `kind:'error'` 横幅。

#### 5.1.5 文件树 ↔ 磁盘的双向同步（v0.3.9 起，v0.3.12 改为实时）

| 方向 | 做法 |
| --- | --- |
| Kore → 磁盘 | 新建/删除直接落盘，随后 `loadDir(parent)` 重读该目录 |
| 磁盘 → Kore | **桌面端：Rust `notify` 内核监听 → `kore://fs-change` 事件 → 立即刷新**（主路径，≈175ms）<br>兜底：轮询已展开目录（1.5s）+ 窗口获得焦点时立即刷 |

**为什么最终上了文件监听器**：v0.3.9 时用 2 秒轮询是权宜之计 —— 当时本机没有
Rust 工具链，监听器是一次无法在本地验证的改动。但轮询的**延迟下限就是轮询间隔**：
用户拿 Typora 做参照物时，「在资源管理器里删掉一个文件、编辑器里还挂着」是
一眼可见的不同步。所以 v0.3.12 补上了内核监听，轮询退居「保险丝」。

**实现**（`src-tauri/src/watch.rs`）：

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 监听范围 | 整个工作区，**递归** | 「展开」是前端概念，Rust 侧不该知道；递归由内核（Windows `ReadDirectoryChangesW`）完成，代价可忽略 |
| 防抖 | **120ms** | 一次保存会产生多个底层事件（建临时文件 → 改名 → 改属性）。不防抖就会连着重读目录、周期重建 DOM，而 DOM 重建正是「有些行点不进去」的成因 |
| watcher 生命周期 | 存在 `State<WatchHandle>` 里 | `notify` 的 watcher **一旦被 drop 就停止监听**。若只留接收端、让 watcher 随作用域回收，表现是「一个事件都收不到、但也不报错」——极难排查 |
| 换工作区 | 先 drop 旧 watcher 再 watch 新目录 | 否则会同时收到两个工作区的事件，刷新到别的目录去 |
| 监听失败 | 只 `console.warn`，**不抛错** | 网络盘 / 权限受限目录 / 不支持的 fs 都可能拿不到内核通知；此时轮询兜底，功能不退化 |
| 事件载荷 | 只带「变了」的信号 + 受影响路径 | 目录内容仍由前端 `read_dir` 按需拉取，与「打开文件夹」「新建」共用同一套逻辑（含白名单过滤），不出现两条渲染路径 |
| 噪声过滤 | 忽略 `~$*` / `.~*` / `.goutputstream-*` / `*.swp` / `*.tmp` | 这些既不在白名单里、也不该触发刷新 |

**⚠️ 最容易踩的坑：列表没变化时绝不能 `setState`。**
`refreshDir` 会被事件与轮询反复调用，若无脑写入新数组，React 会周期性重建整棵子树 ——
而 click 要求 mousedown / mouseup 落在**同一个元素**上，DOM 一重建就丢 click
（正是历史上「有些行点不进去、要点两三次」的成因，见 `FileTree.tsx` 顶部注释）。
所以 `refreshDir` 先用 `sameList()` 逐项比对，**没变就直接 return**。

**目录被外部删除时**：`refreshDir` 返回「该目录已不存在」，`refreshTree` 据此
把它**连同子目录**的 `dirs` 缓存与 `expanded` 展开态一起摘掉。
只删 `dirs` 不删 `expanded` 的话，下一轮还会去读一个不存在的目录。

**实测**（`E:\WorkBuddy\kore\.work\acc3-realtime.mjs`，8 项全过）：

| 场景 | v0.3.11（2s 轮询） | v0.3.12（内核监听） |
| --- | --- | --- |
| 外部新建文件 | ~2000ms | **178ms** |
| 外部重命名 | ~1993ms | **178ms** |

### 5.2 状态层 `src/state/store.ts`

zustand 单 store，是整个应用**唯一数据源**。字段与职责：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `theme` | `'light' \| 'dark'` | 主题；切换时同时 `applyTheme()` 写 DOM 与 localStorage |
| `mode` | `'tauri' \| 'browser' \| 'unknown'` | 运行形态，状态栏直接展示「桌面端 / 浏览器端」 |
| `rootPath / rootName` | `string \| null` | 当前根目录（桌面端是绝对路径，浏览器端是虚拟根） |
| `expanded` | `Record<string, boolean>` | 目录树展开态，key 为路径 |
| `dirs` | `Record<string, FileNode[]>` | **按需缓存**的目录列表（懒加载，只在展开时拉取） |
| `tabs` | `OpenTab[]` | **单文档模式：恒为 0 或 1 个元素**。元素为 `{ id, path, name, content, savedContent, dirty }` |
| `active` | `string \| null` | 当前文档的 `id`（**不是 path** —— 未命名文档没有 path） |
| `pendingSwitch` | `(() => void) \| null` | 非 null 时显示未保存确认对话框；存的是「待执行的切换动作」 |
| `previewHtml` | `string` | 已消毒的当前预览 HTML，导出时直接用 |
| `ready` | `boolean` | 启动流程是否结束，决定渲染编辑器还是 Welcome |
| `notice` | `Notice \| null` | 顶部提示条，可带 `action:'regrant'` 渲染成按钮 |

动作：`init / setNotice / regrantRoot / setTheme / toggleTheme / openFolder / loadDir /
toggleExpand / openFile / closeTab / setActive / updateContent / saveActive / newFile / setPreviewHtml`。

设计要点：

- **脏标记由内容比对得出**：`updateContent` 里 `dirty = content !== savedContent`，不做额外记账。
- **错误文案本地化**：`errText()` 把浏览器的英文 `DOMException` 映射为中文（NotFoundError/NotAllowedError/
  SecurityError/TypeMismatchError/QuotaExceededError/AbortError 等共 8 类），因为直接展示 `DOMException` 对用户毫无意义。
- **取消不是错误**：`isAbort()` 判断 `AbortError`，用户在系统目录选择框里点取消时静默返回。
- **关闭标签不拦未保存**：`closeTab` 直接丢弃，不做二次确认（当前版本的有意取舍，见 §8）。
- `newFile()` 用 `untitled.md → untitled-1.md → …` 避开同名，写盘后 `loadDir(root)` 刷新目录再开标签。
- 路径分隔符按环境取：`isTauri ? '\\' : '/'`，保证虚拟路径在浏览器端不被 Windows 反斜杠切乱。

### 5.3 编辑链路（WYSIWYG，无预览面板）

```mermaid
sequenceDiagram
    participant U as 用户
    participant CM as CodeMirror 6
    participant WY as wysiwyg.ts ViewPlugin
    participant ST as zustand store

    U->>CM: 输入
    CM->>CM: docChanged / selectionSet
    CM->>WY: update() → build(view)
    WY->>WY: 线性扫描到可见末尾<br/>隐藏标记 + 挂语义 class
    WY-->>U: DecorationSet 立即生效
    CM->>ST: updateListener → updateContent(id, text)
    Note over ST: tabs 变化不重建编辑器视图
```

三条稳定性保证：

1. **编辑器视图只按 `[active, theme]` 重建**（`Editor.tsx`）：`updateContent` 会改 `tabs`，但绝不能进依赖数组，
   否则每次按键都重建 CodeMirror 视图 → 光标跳动 + 卡顿。代码注释里明确标注了这条约束。
   主题切换还额外走 `themeCompartment.of(oneDark / [])`。
2. **装饰重算的三个触发条件**（`wysiwyg.ts`）：`docChanged || selectionSet || viewportChanged`。
   `selectionSet` 必须包含 —— 「光标所在行不隐藏标记」是核心行为，
   光标一动就得重算，否则标记显示状态会滞后一行。
3. **图片与复选框用 Widget 而非纯装饰**：
   - `CheckboxWidget` 点击时 `dispatch` 把 `[ ]` 改成 `[x]`（长度相同 → 光标不跳），
     并 `mousedown preventDefault` 避免编辑器抢焦点。
   - `ImageWidget` 的 `ignoreEvent()` 返回 `true`，因此**必须自己在 `toDOM` 里
     监听 mousedown**，把光标 dispatch 到图片语法起点；否则图片独占一行时
     整行点击毫无反应（同样两条约束：`preventDefault` → `focus` → 再 `dispatch`，
     顺序错会导致图片立刻又渲染回 `<img>`）。
4. **每条行内规则的 `head`/`tail` 必须覆盖它 claim 的全部区间**（v0.3.6 修复，见下）：
   `claimed.push([from, to])` 把整段标记为「已占用」，但 DOM 里只会生成
   `hideInline` 真正藏起来的那几段。两边不一致时，多出来的那段就成了
   **点不进去的死区**。

> markdown Worker（`src/lib/markdown.ts` + `workers/markdown.worker.ts`）**仍在**，但只服务
> 导出与打印（§5.6），不再参与屏幕渲染 —— 编辑期零 Worker 开销。

#### 5.3.1 ⚠️ 铁律：内容区禁止纵向 margin

**现象**：鼠标点某一行，光标却落到**下一行**。
用户实测文档：`技术方案/202609/网关安全与性能检查报告.md`，
代表位置是 `### 1.1 高危：…`（紧跟在一个表格后面）。

**根因不在 CodeMirror，而在我们的 CSS。**

CM 用 `elementAtHeight` 逐像素反查「这个 y 属于哪个块」，它只认盒子的
**border-box** —— **`margin` 在盒外，CM 完全看不见**。
于是任何纵向 margin 都会让 DOM 里元素的位置比 CM 的记账低一截，
后续所有行的点击整体偏位。

`@codemirror/view` 对 `block: true` 的替换装饰有明确要求：
> block-level decorations should not have vertical margins

**实测数据（真实文档，采样点铺满整行）**：

| 偏移源 | 单处偏移 | 累计效果 |
| --- | --- | --- |
| `.cm-md-table-wrap { margin: 0.6em 0 }` | 9.6px（上）+ 9.6px（下） | 表格下方所有行偏移 |
| `.cm-md-hr { margin-top: 0.6em }` | 9.6px / 每个 `---` | **4 个分隔线累加 38px** |

38px 已超过半行高（14.5px）→ 点击判定到下一行。

| 状态 | 累计偏移 | 逐行点击结果 |
| --- | --- | --- |
| 修复前 | 38px | 65 行中 **52 行落错** |
| 修复后 | **0px** | 65 行中 **0 行落错** |

**修法**：纵向间距一律用 `padding` 表达（在盒内，CM 量得到，视觉等价）。
已在 `global.css` 加全局防线，防止将来新增样式时重犯：

```css
.editor-host .cm-content * {
  margin-top: 0 !important;
  margin-bottom: 0 !important;
}
```

**⚠️ 排查这类问题的正确姿势**（我在这里走过一大段弯路）：

1. 先量「CM 的 `lineBlockAt(n).top`」与「DOM 里对应元素的 `top`」的**差值**，
   逐元素列出，找出偏移跳变点和累计值；
2. 用 `getComputedStyle(el)` 扫一遍内容区的 `marginTop` / `marginBottom`，
   任何非 0 的纵向 margin 都是嫌疑；
3. **不要**一上来就怀疑 CodeMirror 或去改 Widget 结构
   （`requestMeasure` / 逐行替换 / `atomicRanges` / 每行独立 table
   我都试过，全是无效的弯路 —— 因为真正的元凶是 CSS）。

#### 5.3.2 顶栏菜单：事件顺序与光标约定

> 本节记录「顶栏菜单」三条交互修正（鼠标样式、点空白收起、悬停即切换）。
> 三者看起来互不相关，实际都源自同一个盲点：**没搞清 React 18 的事件委托落点**。

**关键事实：React 18 把 `onClick` 委托在 `#root` 容器上，而不是 `document`。**

于是同一次点击里，冒泡顺序是：

```
.menu-trigger 的 onClick（组件）  →  #root 的 React 委托  →  document（原生监听）
```

这有两个反直觉的后果：

1. **祖先冒泡早于目标冒泡**。`#root` 是 `.menu-trigger` 的祖先，所以它的
   bubble 监听会**先**于按钮自己的 `onClick` 触发。任何「在更外层先改状态、
   再让按钮读状态」的写法都会读到过期值。
2. **状态更新是异步的**。同一次事件里 `setOpen(x)` 之后紧接着读 `open`，
   拿到的仍是旧值 —— 所以「点击同一个菜单名即关闭」这种 toggle 必须读
   `useRef` 里同步的最新值（见 `MenuBar.tsx` 的 `openRef`）。

**最终实现（三条交互）**：

| 交互 | 做法 | 踩过的坑 |
| --- | --- | --- |
| 悬停时鼠标样式 | 全局 `button { cursor: default }`，只给「行动号召」类按钮（欢迎页、提示条 action）与下拉菜单项单独设 `pointer` | 全局 `button { cursor: pointer }` 会让顶栏菜单名、页签、文件树全部变成手型 |
| 点空白收起 | 关闭监听放 **`click`（冒泡）**于 `document`，条件是**祖先白名单**：命中 `.menu-trigger` 或 `.menu-pop` 才放过，其余一律 `setOpen(null)` | v0.3.7~v0.3.11 的条件是「目标不在 `.menubar` 内」→ 顶栏 33px 高的整条都是死区（见下）；v0.3.12 收紧为「只认菜单名与浮层本身」 |
| 悬停即切换 | `.menu-root` 的 `onMouseEnter` → 仅在**已有菜单展开**（`anyOpen`）时切换 | 无条件 hover 开菜单会让鼠标扫过顶栏就乱弹 |

**v0.3.12 修正：关闭条件从「整条顶栏」收到「只看祖先是不是菜单」**

用户报的是「点菜单附近的空白，二级菜单不消失」。复现时在顶栏上铺了 4 个探针点，
**全部**不触发关闭：

| 探针位置 | x 坐标 | 旧条件判定 |
| --- | --- | --- |
| 顶栏左内边距 | 4 | 在 `.menubar` 内 → 不关 |
| 顶栏上沿 / 下沿（33px 高） | 任意 | 同上 |
| 相邻菜单名之间的 2px 缝 | 71 | 同上 |

根因是**判定粒度太粗**：`.menubar` 是横贯整屏的一条（含 8px 左右 padding、菜单名之间
仅 2px 的间隙），以它做边界等于把整个顶栏划成「点哪儿都不关」。用户直觉里的
「附近空白」正好落在这条带子里。

改为精确到**可控元素**：

```ts
const onClick = (e: MouseEvent) => {
  const t = e.target
  if (!(t instanceof Element)) return
  // 菜单名本身：交给它的 onClick 做开/关切换，这里不插手
  if (t.closest('.menu-trigger')) return
  // 已展开的浮层（一级 / 二级）内部：点菜单项由 onPick 负责关闭；
  // 点在浮层的 padding 上则保持展开（用户在菜单里，不该被误关）
  if (t.closest('.menu-pop')) return
  setOpen(null)
}
```

语义变成：**只要不落在「菜单名」或「任意一层浮层」上，就收起** ——
顶栏的 padding、图标空隙、菜单名之间的缝，以及正文/侧栏/状态栏，统统会关。
「手抖点偏」的顾虑由 `.menu-trigger` 吸附解决：菜单名自身有足够宽的点击区，
真正相邻的只剩那 2px 缝，点中它的概率远低于「点左内边距想关菜单」的收益。

验收：Headless Chrome 注入 8 个探针（4 个原死区点 + 4 个应保持展开点），
**21/21 断言通过**，其中 4 个原死区点全部收起、`.menu-pop` 内部点击仍保持展开。

**排查这类问题的正确姿势**：把监听器按阶段打点，打印**真实的事件顺序**
（capture / bubble、target / ancestor），不要凭「常识」假设
「document 上的监听一定最先跑」—— React 的委托落点决定了它未必。
另外，判定「点在不在某区域内」时，**先量那个区域的真实几何**（这里量出的是
「33px 高、横贯整屏」，不是脑子里的「几个菜单名」），再决定拿谁做边界。

#### 5.3.3 ATX 标题：`#` 必须跟空格才成标题（v0.3.12）

**现象**：输入 `#` 的**瞬间**整行变成标题样式 —— 屏幕上是空的一大号字行，
既看不到刚敲的 `#`，也不像「正在输入一个标题」，像误触了什么开关。

**根因**：`wysiwyg.ts` 的 `HEADING_RE` 原来是

```ts
const HEADING_RE = /^(#{1,6})(\s+|$)(.*)$/
//                                ↑ 这个 |$ 是元凶
```

`|$` 是为了兼容 CommonMark 的「空 ATX 标题」（`#` 单独一行也算一级标题）。
但我们的 WYSIWYG 会把标题的标记段 `#` 用 `hide()` **藏起来**，于是
`#` 刚敲下就命中该规则 → `#` 被隐藏 → 整行只剩一个空字符串 →
用户看到「字没了、行变高了」。

规范上没错，**体验上错**：需求要的是 Typora 的手感 —— 敲 `#` 时它还是
一个普通字符，敲完空格才升级成标题。

**修法**（一行）：

```ts
const HEADING_RE = /^(#{1,6})(\s+)(.*)$/
```

去掉 `|$` 分支后，只有「`#` + 至少一个空白」才算标题；单独一个 `#` 就是
普通文本，原样显示。**空 ATX 标题不再被识别**，但这正是想要的语义
（想写空标题只需敲 `# ` 再删掉后面的内容，光标行不隐藏标记仍可编辑）。

> 顺带确认 `src/lib/outline.ts` 的大纲正则 `/^(#{1,6})\s+(.*\S)\s*#*$/`
> **本来就要求 `\s+` 且要求标题有非空内容**，与修改后的编辑器行为一致，
> 无需改动 —— 两处规则此前就不同步，现在对齐了。

**验收**：单元测试 11/11 通过（`#` / `##` / `######` 不成标题；`# ` / `## ` /
`# 标题` / `###### 标题` 成标题；`####### x` 因超过 6 个不成标题；
`#标题` 无空格不成标题）。页面级断言并入 §5.3.2 的 21 项。

**这条踩坑的通用教训**：WYSIWYG 里「符合规范」和「符合手感」经常冲突，
凡是涉及**隐藏标记**的规则，都要退一步想「标记被藏起来之后，用户还看得见什么」。
`#` 变空标题就是典型：规范合法，但把用户唯一的输入反馈也一起藏没了。

#### 5.3.6 分割线（HR）：保持线条外观 + 输入自动落到下一行（未发布，攒批）

**Bug**：在分隔线下方打字，内容会被并进 `---`，变成 `---测试`，横线也随之消失。
根因是**视觉误导**：`.cm-md-hr` 用 `padding-top: 1.5em + border-top` 画线，
整行 `---` 又被 replace 装饰隐藏 —— 隐藏文本里的光标视觉上落在横线**下方**，
看起来像"下一行"，其实光标仍在 `---` 这一行。

**修法**（`wysiwyg.ts` 的 `hrInputGuard`，**不改横线外观**）：

- **线条始终是线条**：光标放上去也保持横线，不回退成 `---`（更符合操作习惯）。
- **输入守卫**：在分隔线上输入非 `- * _` / 空白的字符时，先补一个换行再把内容
  放到下一行：`---` + 「测试」→ `---\n测试`。继续敲 `-`/`*`/`_`/空格直接放行，
  这样 `----`、`- - -` 仍是在延长同一条分割线，不会被强行断行。
- **回车守卫**：光标在分隔线任意位置按 Enter，统一落到行尾之后，
  绝不把 `---` 劈成 `-\n--`。
- 代码块里的 `---` 不是分割线：用 `syntaxTree` 判断是否落在
  `FencedCode / CodeBlock / CodeText` 内，命中则完全不拦截。

**入口**：斜杠菜单新增 `HR 分割线`（keys: `hr` / `分割线` / `分隔线` / `fgx` /
`---` / `rule` / `hline`），插入 `---` + 换行，光标直接落到下一行；
若 `/hr` 前面还有正文，会先补一个换行，保证横线独占一行。
也可手打 `---`（或 `***`、`___`）后按 Enter。

### 5.4 大纲与跳转
- `extractOutline()`（`src/lib/outline.ts`）：逐行扫，用 `inFence` 状态机跳过代码块内的 `#`。
  状态机记录围栏字符（``` vs ~~~），避免代码块内出现的另一种围栏被误判为闭合。
  返回**行号 `line`（1 起）**，不再返回可跳转的 DOM 锚点。
- 跳转链路：点击大纲项 → `setJumpLine(line)` → `Editor.tsx` 的 effect 里
  `lineToPos(state, line)` 换算绝对位置 → `dispatch({ selection, effects: EditorView.scrollIntoView(pos, { y: 'start', yMargin: 24 }) })` → 聚焦。
  用**行号**而非 DOM id，是因为 WYSIWYG 下根本不存在锚点元素。
- `slugify()`（`src/lib/slug.ts`）仍然保留，产出的 `id` 只用于导出 HTML（与 `markdown-it-anchor` 对齐）。

### 5.5 主题与视觉

- `tokens.css` 定义两套 CSS 变量（亮色 `--bg #ffffff` / 暗色 `--bg #1b1f27`），切换只改 `document.documentElement.dataset.theme`，零重渲染。
- `theme.ts`：`localStorage['kore-theme']` 优先，未设置时回落 `prefers-color-scheme`。
- Logo 四件套由 `scripts/gen_logo.py` 从品牌源图生成（抠底 → 用 HSV 的 value 分色藏青 #394958 / 青 #209EBB → 连通域切 K 标记 → 出图），
  `logo.ts` 按主题返回 `markSrc/wordmarkSrc`，组件只换 `src`。
- 打印样式：`global.css` 的 `@media print` 把整个 `.app` 隐藏（`display:none !important`），
  只显示 `lib/export.ts` 动态创建的 `#kore-print-root`（内含 Worker 渲染 + 消毒后的 HTML）。
  「导出 PDF」= 渲染 → 注入 `#kore-print-root` → 等两帧 → `window.print()` → 系统打印对话框「另存为 PDF」。

### 5.6 导出

| 方式 | 桌面端 | 浏览器端 |
| --- | --- | --- |
| 导出 HTML | 同名 `.html` **写回源文件同级目录** | `Blob + a[download]` 触发本地下载 |
| 导出 PDF | 渲染 → 注入 `#kore-print-root` → `window.print()` | 同左 |

两条导出路径都走同一个前置：`renderSafe(src)` = **Worker 渲染 markdown-it → DOMPurify 消毒**。
与 v0.1.0 的区别是内容来源从常驻预览面板的 `previewHtml` 改成**按需渲染当前标签的 `content`**，
因此导出内容与屏幕所见严格同源（WYSIWYG 下「所见」不是真 HTML，只有重新渲染才能得到带样式的完整文档）。

`buildHtmlDoc()` 生成自包含单文档：内嵌样式，背景/前景/代码块/引用/表格按当前主题取色，
`.anchor-link`、图片 `max-width:100%`、`h1~h3` 加 `scroll-margin-top`。

### 5.7 桌面端 Rust 侧

**文件读写**（`commands.rs`）三个命令，全部同步阻塞式 IO，无异步、无并发
（并发由 WebView 单线程 + 用户操作节奏天然串行）：

| 命令 | 实现 | 失败语义 |
| --- | --- | --- |
| `read_dir(path)` | `fs::read_dir`，跳过 `file_type()` 异常项；目录优先 + 小写名排序 | `Result<Vec<FileEntry>, String>`，错误即中文前缀文案 |
| `read_file(path)` | `fs::read_to_string` | 同上 |
| `write_file(path, contents)` | `fs::write`（覆盖） | 同上 |

**文件监听**（`watch.rs`，v0.3.12 新增）：

| 命令 | 实现 | 失败语义 |
| --- | --- | --- |
| `watch_workspace(path)` | 用 `notify`（v6）的 `recommended_watcher` 递归监听工作区根目录；事件先进 `mpsc`，由后台线程以 **120ms 静默窗口**（`recv_timeout`）聚合成批，再 `emit` 一次 | `Result<(), String>`；同根目录重复调用幂等（先 drop 旧 watcher） |
| `unwatch_workspace()` | `take()` 掉 watcher（**drop 即停止监听**），清空 root | 永不出错（`Result<(), String>` 恒 `Ok`） |

- **事件名 `kore://fs-change`**，载荷 `{ paths: Vec<String> }`（排序去重后的受影响路径）。
  前端只把它当「该刷新了」的信号，不用 paths 做增量 —— 全量 `refreshTree()` 在
  千文件级目录下也就几十毫秒，比维护增量一致性便宜得多。
- **必须把 watcher 存进 `State`**：`WatchHandle(Mutex<WatchState>)`，`lib.rs` 里
  `.manage(WatchHandle::new())`。`notify` 的 watcher 一旦被 drop 就**静默停止**
  监听（不报错、不抛异常），是本模块最容易踩的坑。
- **噪音过滤** `is_noise()`：忽略 `~$*`（Office 锁文件）、`.~*`、`.goutputstream-*`
  （GNOME 写入临时名）、`*.swp` / `*.swx`（vim）、`*.tmp` —— 否则编辑器写盘时会
  自我触发一串无意义的刷新。
- **回退路径**：`fsApi.watchWorkspace()` 在浏览器模式（无 Tauri 运行时）或
  监听启动失败时返回空 dispose，前端退回 1.5s 轮询（`TREE_SYNC_MS`）。
  失败只 `console.warn`，不打扰用户 —— 「不够实时」比「弹个错误」可接受。
- 权限面收敛在 `capabilities/default.json`：
  `core:default / core:event / core:window / core:app` +
  `core:webview:allow-create-webview-window`（「新建窗口」需要）+
  `dialog:default / dialog:allow-open / dialog:allow-save`。
  应用自有命令默认放行，不额外声明。`core:event:default` 已含 `allow-listen`
  / `allow-unlisten`，前端 `listen('kore://fs-change')` 不需要额外 ACL。
- `main.rs` 用 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` 屏蔽 release 窗口控制台。
- `Cargo.toml` release profile：`panic="abort"` + `lto=true` + `codegen-units=1` + `opt-level="s"` + `strip=true`，
  目标是极小的 release 体积（与「安装包 2~3MB」的产品目标对应）。
- `tauri.conf.json` 里 `csp: null` —— 当前未设 CSP（见 §8 技术债）。

```mermaid
flowchart LR
    S["源码"] --> N["scripts/check-node.mjs<br/>Node ≥ 18 守卫"]
```

- `npm run build` = `tsc --noEmit && vite build`，类型错误直接阻断产物。
- `base: './'`：产物走相对路径，才能被 Tauri 自定义协议加载。

  （避免单一平台 lock 固化原生 optional 依赖，npm bug #4828）→ `tauri build` → 上传 Release。
- Windows MSVC 目标需要 VS 生成工具提供 `link.exe`（外部环境依赖）；
  `scripts/install-rust.ps1` 只保证 `CARGO_HOME`/`RUSTUP_HOME` 落在非 C 盘。
- ⚠️ `@tauri-apps/*` 在 `package.json` 里**必须写精确版本**（不带 `^`），并且与
  `src-tauri/Cargo.lock` 里对应 crate 的 `major.minor` 对齐。
  CI 会先删掉 `package-lock.json` 再 `npm install`，`^` 范围就等于「构建时拉 npm 最新版」；
  而 Rust 侧用的是仓库里锁死的 `Cargo.lock`。`tauri build` 一开始就会校验这两边的版本，
  对不上直接失败 —— v0.3.14 首次发版正是栽在这：`tauri-plugin-updater (v2.13.3)` 对
  `@tauri-apps/plugin-updater (v2.14.1)`。升级插件时 npm 与 Cargo 两边一起改。
- 自检：`npm run check:tauri`（`scripts/check-tauri-versions.mjs`）。按 Tauri 自己的规则只比
  `major.minor`，顺带拦「写了 `^` / `~`」这个根因；`Cargo.lock` 不存在时静默跳过（纯前端开发无感）。
  CI 在 `npm install` 之后、`tauri build` 之前单独跑这一步，失败原因会出现在独立步骤里。

### 5.10 应用内自动更新（v0.3.10）

需求原话：「直接下载，下载后提示安装然后重启，而不是让用户自己去浏览器下载」。

**用的是 Tauri 官方 updater 插件**，链路：

```
点击「立即更新」
  → check()          取 endpoints 上的 latest.json（签名 + 下载地址）
  → downloadAndInstall(进度回调)   下载 → 校验签名 → 启动安装器
  → relaunch()       Windows 上通常执行不到（见下）
```

| 关键点 | 说明 |
| --- | --- |
| **签名校验无法关闭** | 必须生成密钥对：私钥在仓库 Secret，公钥写进 `tauri.conf.json`。**私钥丢失 = 已安装用户永久收不到更新** |
| 更新清单 | `https://github.com/renxf0319/kore/releases/latest/download/latest.json`，由 tauri-action 在签名构建时自动生成上传 |
| `createUpdaterArtifacts` | 必须为 `true`，否则不产出 `.sig` 与更新包 |
| **Windows 会自动重启** | 插件给 NSIS 传 `/S /R`，安装完由安装器拉起应用；所以 `relaunch()` 在 Windows 是「到不了的一行」，macOS / Linux 才靠它 |
| 进度反馈 | 复用顶部提示条。**只在整数百分比变化时**才 `setStatus` —— 下载事件按 chunk 高频触发，每次都 setState 会让文字抖动 |
| 失败退路 | 任何一步失败都退回「前往下载」（浏览器下载页），不把用户卡在一条点不动的错误上 |

**入口**：发现新版本时**提示条上的「立即更新」**（v0.3.13 后唯一入口；
原「关于」菜单里的「下载并安装更新…」已按需求删除，见 §5.3.4）。
进入更新的触发方式是「关于 → 检查更新…」，发现新版后提示条给出「立即更新」。
浏览器模式下不提供应用内更新（没有 Tauri 运行时），只显示「前往下载」。

**CI 防呆**：`createUpdaterArtifacts` 在缺少签名私钥时会让构建**直接失败**。
为了「没配密钥也能正常出安装包」，workflow 里加了一步预检：
检测不到 `TAURI_SIGNING_PRIVATE_KEY` 就把该配置摘掉再构建，
只损失更新清单，安装包照常产出。

**密钥存放**：`E:\WorkBuddy\kore-signing\kore-updater.key`（**刻意放在仓库之外**，
避免误提交）。必须异地备份。

#### 5.10.1 为什么 Windows 只出 NSIS（`.exe`）

`tauri.windows.conf.json` 把 Windows 的 `bundle.targets` 覆盖成 `["nsis"]`
（基础配置仍是 `"all"`，将来恢复 macOS/Linux 不受影响）。

起因是一个真实的隐患：同时构建 `msi` 与 `nsis` 时，`latest.json` 会同时出现
三个 Windows 键 ——

```
windows-x86_64        → ……_x64_en-US.msi
windows-x86_64-msi    → ……_x64_en-US.msi
windows-x86_64-nsis   → ……_x64-setup.exe
```

通用键 `windows-x86_64` 指向的是 **MSI**。而用户装的是 `.exe`（NSIS）。
两者格式不一致时，Windows 可能出现**重复的「应用和功能」条目**
（tauri-apps/tauri#12365 就是在修这个）。

只出 NSIS 之后，清单里 Windows 只有一个条目、且与用户实际安装的 `.exe` 一致，
再不存在「选中了另一种格式的安装包」这种可能。

**代价**：不再产出 `.msi`（原先注释写的是「供企业部署」）。
本项目目前没有企业分发的需求，用不上却要背这个风险，不划算。
若将来确实需要 `.msi`，把 `tauri.windows.conf.json` 删掉即可恢复 —— 但要同时
接受上面那个歧义，或改用只出 MSI 的配置。

## 6. 典型数据流时序

### 6.1 首次打开一个文件夹

```
工具栏「打开文件夹」 → openFolder()
  → fsApi.pickFolder()        桌面：原生对话框 / 浏览器：showDirectoryPicker
  → 设置 rootPath/rootName、expanded[root]=true
  → fsApi.persistRoot()       桌面：localStorage / 浏览器：IndexedDB
  → loadDir(root) → fsApi.listDir() → dirs[root] = FileNode[]
  → Sidebar 渲染根目录节点 + 子节点
```

### 6.2 打开文件 → 编辑 → 保存（单文档）

```
点击文件        → openFile(path, name)
                   → 已是当前文件则直接返回（不弹拦截）
                   → fsApi.readFile() 读成功后 guard()：
                      · 当前文档干净 → 直接覆盖
                      · 当前文档 dirty → 弹「保存 / 放弃 / 取消」
展开目录        → toggleExpand(path) → loadDir(path)（懒加载，按需）
CodeMirror 输入  → updateListener → updateContent(id, text) → dirty 自动置位 + 底部栏出现圆点
Ctrl/Cmd + S    → keymap 'Mod-s' → save() → 无 path 则转 saveAs() → writeFile → dirty=false
关闭文档        → requestClose() → guard() 同上
```

## 7. 两种运行模式对比

| 维度 | 桌面端（Tauri） | 浏览器端 |
| --- | --- | --- |
| 选目录 | 原生窗口 `tauri-plugin-dialog` | `showDirectoryPicker()`（Chrome/Edge） |

## 8. 已知约束与技术债

按「影响面 × 修复成本」排序，供后续迭代参考：

| # | 项 | 现状 | 建议 |
| --- | --- | --- | --- |
| 1 | **无自动保存 / 无崩溃恢复** | 只靠手动 `Mod+S`，进程崩溃即丢草稿 | 可选：写入前把 `savedContent` 快照放 IndexedDB，启动时提示恢复 |
| 2 | **WYSIWYG 覆盖的语法有限** | 标题/粗斜体/删除线/高亮/行内代码/链接/图片/引用/列表/任务/围栏/分割线/**表格**已支持；**脚注、定义列表、HTML 块仍是源码** | 脚注可仿照表格用 `Decoration.replace` + Widget 实现；或在文档里明确标注「复杂块请用导出预览」 |
| 3 | **无 CSP** | `tauri.conf.json` 里 `"csp": null` | 补 CSP 白名单（本机静态资源 + blob:），降低 WebView 注入面 |
| 4 | ~~**目录树不自动刷新**~~ | **v0.3.12 已解决**：桌面端接 `notify` 实时监听（§5.1.5 / §5.7），浏览器端仍只能手动 `loadDir` | 浏览器端如需实时，只能引导用户走桌面端；`FileSystemObserver` 规范尚未在稳定版 Chrome 落地 |
| 5 | **并发/外部写覆盖** | `write_file` 无条件覆盖，无时间戳/版本号校验 | 超小型工具可接受；若要加强，可加 mtime 比对 |
| 6 | **编辑器视图随切文件重建** | 撤销历史（`history()`）不跨文件保留，滚动位置丢失 | 如要跨文件撤销，改为按 `id` 缓存多份 `EditorState` |
| 7 | **装饰引擎线性扫描全文** | 为保证围栏状态正确，每次重算都从第 1 行扫到视口末尾 | 万行内可接受；超大文档可加「围栏状态缓存」或改用增量解析 |
| 8 | **大目录首屏加载** | `dirAt()` 逐层 `getDirectoryHandle`，深目录展开有轻微延迟 | 可接受；若卡顿明显可并行化 |
| 9 | **无移动端适配** | 定宽桌面布局（min 760×560） | 移动端若要做需把左侧栏改为抽屉 |
| 10 | **`package-lock.json` 不跨平台** | CI 里刻意 `rm -f` 后重装 | 已是约定，勿回退 |
| 11 | **多标签已移除** | v0.3.0 按需求改为单文档 | 若要恢复多标签，`tabs` 数组结构与 `guard` 拦截可直接复用（把 `single()` 换成 push 即可） |

### 表格渲染支持（WYSIWYG）

**新增**

- `src/styles/global.css` —— `.cm-md-table-*` 样式，全部走主题变量，明暗自动适配

**关键决策与踩坑**
- 装饰来源从 `ViewPlugin` 换成 **StateField + `EditorView.decorations`**：
  表格是块级替换（`block: true`），CodeMirror 禁止 ViewPlugin 提供块级装饰，
  会抛 `RangeError: Block decorations may not be specified via plugins` 并打崩 DocView。
  **这类错误 `tsc` 与 `vite build` 都发现不了，只有真跑页面才暴露。**
- 光标行同步用 **`EditorView.updateListener`** 而非 `ViewPlugin.update`：
  后者在纯选区变化时不一定被触发（实测光标在表格内外移动，调用计数纹丝不动），
  且失败是静默的 —— 表现为「光标进了表格却不回落源码」，无任何报错。
- 防循环只靠一条铁律：**行号真的变化才 dispatch**。试过的两种「聪明」写法
  （自锁标志位、跳过自己 dispatch）都会在状态错位后静默吞掉后续所有更新。
- 扫描范围是整篇文档，**不能用 `visibleRanges`**：块被替换后 CodeMirror 会把该区间
  从 visibleRanges 里挖掉，拿它当依据会让表格被自己的渲染结果挤出扫描范围。
- 交互：光标不在表内 → 渲染表格；点击单元格 → 光标送到该格源码位置、整块回落源码；
  光标移出 → 自动渲染回表格。分隔行 `|---|` 在源码态也会隐藏。
- 顺带修好**嵌套行内语法**：`claimed` 去重改为只拦「完全覆盖」的同级命中，
  命中内层规则后递归渲染子树，因此 `**无 `${}`**` 能同时呈现粗体与行内代码。

- **GBK 是「乱码」的真正来源，且与扩展名无关**：`.txt` / `.sql` 完全可能是 GBK 编码。
  浏览器端 `File.text()` 用的是**宽松解码**，非法字节替换成 `U+FFFD`，
  实测 GBK 的「中文测试」会解成 `���Ĳ���` —— 满屏替换字符，正是需求里要消灭的乱码。
  改用 `TextDecoder('utf-8', {fatal: true})` 解不出就明确提示「请转存为 UTF-8」。
  桌面端对应 `fs::read` + `String::from_utf8`，并按 `valid_up_to() == 0` 区分
  「二进制」与「编码不对」两种成因。
- **非 md 必须退出 Markdown 装饰，否则就是乱码**：WYSIWYG 会把 `# 端口注释`
  当标题把整行藏掉、把 `*` / `_` / `- ` 当强调与列表标记吃掉。
  实测 `.sql` 打开后 `FROM users` 完整可见、`# 端口注释` 逐字保留，才算修对。
  这条**只跑 `tsc` / `vite build` 发现不了**，必须真跑页面看渲染结果。
- **闸门要放两处**：调用方（store）判一次是为了不打扰用户（不发请求、不弹未保存拦截），
  `fsApi.readFile` 里再判一次是因为它是**所有读盘的唯一出口**。
  只判一处就留下「绕过 UI 直接调 command」的漏洞。
- **提示用 `info` 而不是 `error`**：红色报错条表达的是「程序坏了」，
  而「这个类型不支持 / 编码不对」是范围问题，前者会让用户以为要重装。
  故新增 `NotOpenableError` 让 store 能把它渲染成中性提示。
- **Rust 侧拿不到错误类型**（Tauri 只回 `Err(String)`），所以桌面端的编码提示
  靠文案特征 `/转存为 UTF-8|不是 UTF-8/` 识别，避免又被套一层「打开失败：」前缀。
- **顺带修掉一个既有 bug**：`saveAs` 原来无条件把文件名改成 `.md`
  （`ensureMdExt`），支持多类型后「打开 a.sql → 另存为」会**静默把文件类型换掉**。
  改为 `keepExt()`：已有受支持扩展名就保留，没有才回落 `.md`。
  `exportHtml` 的 `.html` 命名同理改为剥掉任意扩展名。
- 验证方式：headless Chrome + 伪造 File System Access 目录句柄，
  注入 md/sql/yaml/conf/properties/txt/class/无扩展名/GBK-txt 十种文件，
  逐条断言可见性、编辑器 class、字体、提示条 `kind` 与文案。

  新增 `.sidebar-resizer` 与 `body.resizing-col`

**拖拽实现的三个要点**（改这个文件前务必知道）：

1. **必须用 pointer 事件 + `setPointerCapture`**，不能用 mousedown/mousemove ——
   指针移出把手后 mousemove 会丢；`setPointerCapture` 让指针划出窗口仍继续响应。
2. **拖动时给 `body` 加 `.resizing-col`**（`user-select:none` + 全局 `cursor: col-resize`）。
   否则鼠标移过快会「失去跟踪」，并误选正文文字。
3. **监听挂在 `window` 上**，不挂在把手元素上 —— 否则 React 重渲染换掉 DOM 节点后监听丢失。

**宽度范围取 [140, 520] 的理由**：小于 140px 中文文件名几乎不可读；
大于 520px 编辑区会比侧栏还窄，主次颠倒。
